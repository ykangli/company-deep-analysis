# 数据真实性校验协议（强制）

> 本协议是本 skill 的**核心质量保证机制**。任何偏离都必须写入报告的"数据来源与时效性说明"。
> 目标不是"数据好看"，而是**每一个承重数字都能被第三方复现**。

---

## 一、三级来源分级

给每个数据点标注来源级别，级别决定它在报告里的措辞强度。

| 级别 | 定义 | 报告中标记 | 能否作为结论依据 |
|:----:|------|:---------:|:---------------:|
| **L1 一手法定披露** | 监管申报原文（SEC EDGAR 的 8-K/10-Q/10-K；巨潮/交易所公告；HKEX 公告）、公司官方财报新闻稿 | `【已核实】` | ✅ 可以 |
| **L2 官方数据接口** | 交易所或权威数据商的结构化接口（东方财富、新浪财经、Yahoo Finance、akshare 封装的官方接口）、官方 IR 页面 | `【已核实】`（须注明接口名与取数时间） | ✅ 可以 |
| **L3 二手转述** | 财经媒体报道、券商研报摘要、第三方汇总站、搜索引擎返回的标题与摘要 | `【二手转述】` | ⚠️ 只能作为线索，**承重结论必须回溯到 L1/L2** |

**硬性规则：报告"零、核心结论摘要"与"十二、最终结论"中出现的每一个数字，来源级别必须是 L1 或 L2。**

---

## 二、五个必做的校验动作

### 1. 交叉验证（Cross-check）

同一个承重数字，**至少用两个独立来源核对**。若两者不一致：

- 优先采用 L1；
- 若同为 L1 却不一致，说明是**口径差异**（见第三节），必须在报告中写明两个口径与差异原因；
- **绝不允许**直接取其一而不做说明。

### 2. 加总校验（Reconciliation）

`compute_metrics.py` 自动执行，失败即中止：

- 各分部收入之和 = 总收入（允许 ≤0.5% 的舍入差）；
- 资产 = 负债 + 权益；
- 四个季度之和 = 全年（≥2% 的差异即报警）；
- 现金流量表期初现金 + 净变动 = 期末现金；
- 净利 ÷ 期末股本 ≈ EPS（用于反推股本）。

**若加总校验失败**：说明取数或口径有误，必须停下来排查，不得"忽略误差继续写"。

### 3. 常识校验（Sanity check）

逐项问自己：

- 这个数字的量级对吗？（例：某季度分部收入是否超过了公司总收入？）
- 同比增速与绝对值是否自洽？
- 净利率是否超过 100%？（若超过，说明存在大额非经营性损益，必须去二.6 节剥离）
- 毛利率、净利率、营业利润率三者的大小关系是否合理？

**量级错误的典型症状**：中文媒体把"积压订单"写成"季度收入"、把"年度"写成"季度"、单位错位（亿美元 vs 亿元）。**凡与其它来源差一个数量级，先怀疑单位。**

### 4. 反查一手来源（Reverse verification）★ 最重要

**任何来自 subagent、媒体或搜索摘要的承重结论，必须回到一手文件里确认一次。**

具体做法：对已下载的一手文件做全文检索，确认关键事实确实存在。例如：

```bash
# 在一手披露文本中确认某个事实是否真的出现
grep -n "关键词" ./work/primary/*.txt
```

**本规则来自一次真实事故**：一份 subagent 报告把"2026H1 收购现金支出 336.97 亿、商誉从 334 亿增至 578 亿"这一**财务事实**，自行归因为"完成 Wiz 收购"。回到 SEC 原文检索后发现，**"Wiz" 一词在任何一份 8-K 新闻稿与 10-K 摘要中都从未出现**。该归因属于推断，不能写成事实。修正后报告表述为"完成一笔大型收购（标的名称未能核实）"。

**推论**：subagent 的产出默认是 `【二手转述】`。它们的**方向性判断**往往有用，**具体归因经常越界**。

### 5. 时点校验（As-of check）

- 每个数字都要有明确的"截止时点"；行情数据必须注明是收盘还是盘中。
- 财报数据要注明**报告期**与**披露日**，两者不同。
- 若写作当日有财报刚刚发布或即将发布，必须在"时效性说明"中提示。
- 跨期比较必须同口径：不要把"最新单季同比"与"全年同比"混在一张表里比较。

## 三、必须主动排查的六类口径陷阱

| # | 陷阱 | 症状 | 处理 |
|:-:|------|------|------|
| 1 | **一次性收益抬高净利** | 净利率异常高（>50%）、PE(TTM) 显著低于静态 PE | 必须计算"核心净利/核心 EPS"，并在报告显著位置给出失真警告 |
| 2 | **多类股不能相加** | 有的投资人持 A 类、有的持 C 类 | 严格分列；**永不用某一类股数 ÷ 总股本算持股比例** |
| 3 | **13F 是季末市值不是成本** | 媒体用"投入 X 亿"表述 | 成本只能用**已披露的交易价格**推算，并标 `【推算】`；季末市值 ≠ 买入价 |
| 4 | **披露日市价 ≠ 季末价** | 同一持仓出现两个差 15% 的"市值" | 注明口径；报告统一采用季末市值，并说明另一口径的来源 |
| 5 | **期权按名义价值申报** | 13F 中 put/call 与普通股混排 | 期权不与普通股相加、不相除；单独说明 |
| 6 | **子公司/关联方独立申报** | 出现与母公司方向相反的头条 | 确认申报主体（CIK）；标题党常见手法是把子公司持仓写成母公司行为 |

## 四、无法核实的处理方式

**"未能核实"是一个合格的交付内容，不是失败。** 处理规则：

1. **如实写出**，格式为：`未能核实（已检索 A、B、C 三类来源）`——说明你查过什么。
2. **不得用模糊表述替代**："可能"、"据传"、"市场普遍认为"都要么升级为带来源的 `【二手转述】`，要么改为 `未能核实`。
3. **不得用推算填补**：13F 不披露成本，就写"未能核实"，不要用季度均价假装是成本（若确实要推算，必须明写公式与假设，并标 `【推算】`）。
4. **在报告收尾的"未能核实清单"中集中列出**，方便读者知道边界在哪。
5. 若某个 `未能核实` 项**恰好是投资结论的关键变量**，必须明确写出："该项无法核实，因此本报告的结论建立在此假设之上。"

## 五、写作时的自查触发词

出现下列词句时，停下来检查：

| 触发词 | 必须做的事 |
|--------|-----------|
| "约"、"大约"、"近似" | 确认这是 `【推算】` 并写出公式 |
| "据报道"、"有消息称" | 降级为 `【二手转述】` 或改为 `未能核实` |
| "市场预计"、"分析师认为" | 必须有具名机构与日期 |
| "创历史新高/新低" | 必须有历史序列支撑 |
| "大幅"、"显著" | 换成百分比 |
| "完成收购 X 公司" | **反查一手文件是否出现该公司名** |
| "巴菲特/某名人买入/卖出" | 确认申报主体是不是母公司 |

## 六、验收标准

报告交付前必须全部满足：

- [ ] `verify_report.py` 无 error（warning 需逐条说明）
- [ ] 加总校验全部通过
- [ ] 零章/十二章中每个数字均可在正文找到 L1/L2 来源
- [ ] 存在一次性收益时，已给出核心口径与失真警告
- [ ] 所有 `【推算】` 都写出了公式
- [ ] 所有 `未能核实` 都说明了检索范围
- [ ] 所有 subagent 提供的承重数字都已反查
- [ ] 已列出"已剔除/已纠正的数据"
